# friendSheep notify_service

`notify_service` развёртывается как отдельный сервис. Базовая версия P0.2a намеренно
мал: он проверяет конфигурацию окружения, подключается только к собственной
PostgreSQL, применяет встроенные миграции, предоставляет проверки состояния и
готовности и корректно завершается.

Сервис не запускает задания планировщика и не отправляет уведомления. Ему запрещено
читать или изменять базу данных монолита.

## Запуск

Задайте `NOTIFY_DATABASE_URL` по образцу `.env.example`, затем выполните:

```text
go run .
```

Процесс не загружает `.env`. Локальные инструменты разработки могут экспортировать
значения из игнорируемого файла до запуска процесса.

## Проверки состояния

- `GET /health` возвращает `200 {"status":"ok"}`, пока HTTP-процесс работает.
- `GET /ready` проверяет собственную базу данных сервиса и возвращает `200` с
  `{"status":"ready"}` либо `503` с `{"status":"not_ready"}`.

Следующий вертикальный срез добавит надёжные lifecycle jobs, вызывающие
аутентифицированный внутренний lifecycle API монолита. Прямой доступ к таблицам
монолита запрещён.
