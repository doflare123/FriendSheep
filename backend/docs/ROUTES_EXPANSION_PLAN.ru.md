# План добавления роутов (RU)

## 1. Цель
Вернуть недостающий старый функционал и добавить новые API-роуты для:
- групп,
- эвентов,
- профиля пользователя и уведомлений,
- усиленного сценария смены пароля.

Документ фиксирует контракт роутов, обязательные поля и этапы внедрения.

## 2. Общие правила для новых роутов
- Префикс: `/api/v2/...`
- Авторизация: `Bearer JWT` для всех роутов, кроме публичного поиска (если решим открыть поиск групп/эвентов).
- Пагинация: единый формат.
  - Вход: `page`, `limit`
  - Выход: `page`, `limit`, `totalPages`, `totalItems`, `hasNext`
- Ошибки: единый `dto.ErrorResponse`.

## 3. Группы

### 3.1 Получить группы, где пользователь админ/модератор
- `GET /api/v2/users/me/groups/managed`
- Назначение: вернуть группы текущего пользователя, разделенные на два блока.
- Ответ:
  - `admin: []`
  - `moderator: []`
  - Поля элемента:
    - `id`
    - `name`
    - `categories`
    - `smallDescription`
    - `memberCount`
    - `image`

### 3.2 Получить подписки пользователя (участник без админ/модер роли)
- `GET /api/v2/users/me/groups/subscriptions`
- Назначение: группы, где пользователь обычный участник.
- Ответ: список с пагинацией.
- Поля элемента:
  - `id`
  - `name`
  - `categories`
  - `smallDescription`
  - `memberCount`
  - `image`

### 3.3 Поиск групп
- `GET /api/v2/groups/search`
- Назначение: поиск с фильтрацией и без.
- Query (предложение):
  - `q` (строка поиска),
  - `categoryIds` (список),
  - `isPrivate` (`true|false`),
  - `city`,
  - `sortBy` (`createdAt|memberCount|name`),
  - `sortOrder` (`asc|desc`),
  - `page`, `limit`.
- Ответ: список с пагинацией.
- Поля элемента:
  - `id`
  - `name`
  - `categories`
  - `memberCount`
  - `image`
  - `createdAt`
  - `smallDescription`
  - `isPrivate`

## 4. Эвенты

### 4.1 Поиск эвентов
- `GET /api/v2/events/search`
- Назначение: поиск с фильтрацией и без.
- Query (предложение):
  - `q`,
  - `groupId`,
  - `eventTypeId`,
  - `locationType` (`online|offline`),
  - `city`,
  - `genreIds`,
  - `dateFrom`, `dateTo`,
  - `hasFreeSlots`,
  - `page`, `limit`.
- Ответ: список с пагинацией.
- Поля элемента:
  - `id`
  - `group: { id, name }`
  - `image`
  - `currentUsers`
  - `maxUsers`
  - `duration`
  - `startDate` (только дата, без времени)
  - `eventType`
  - `locationType` (онлайн/оффлайн)
  - `city` (если есть)
  - `genres`

## 5. Новости

### 5.1 Получить список новостей
- `GET /api/v2/news`
- Пагинация:
  - `limit` фиксированно `10`,
  - Query: `page`,
  - в ответе: `page`, `totalPages`, `hasNext`.
- Поля новости:
  - `id`
  - `title`
  - `smallDescription`
  - `image`
  - `createdAt`
  - `likesCount`
  - `dislikesCount`
  - `commentsCount`

### 5.2 Получить подробную информацию о новости
- `GET /api/v2/news/{newsId}`
- Поля:
  - `id`
  - `title`
  - `createdAt`
  - `updatedAt`
  - `content` (markdown)
  - `image`
  - `likesCount`
  - `commentsCount`
  - `lastComments` (10 последних комментариев)

### 5.3 Оставить или редактировать комментарий (пользователь)
- Создание:
  - `POST /api/v2/news/{newsId}/comments`
- Редактирование своего комментария:
  - `PATCH /api/v2/news/comments/{commentId}`

### 5.4 Получить больше комментариев к новости
- `GET /api/v2/news/{newsId}/comments`
- Логика:
  - первые 10 отдаются в `news details`,
  - этот рут возвращает следующие страницы.
- Query:
  - `page`, `limit` (по умолчанию 10).
- Метаданные ответа:
  - `page`
  - `totalPages`
  - `totalItems`
  - `hasNext`
- Поля комментария:
  - `id`
  - `userId`
  - `userName`
  - `text`
  - `hasReplies`
  - `repliesCount`
  - `createdAt`
  - `updatedAt`
  - `likesCount`
  - `dislikesCount`

### 5.5 Ответить на комментарий
- `POST /api/v2/news/comments/{commentId}/replies`
- Поля ответа-комментария:
  - `id`
  - `parentCommentId`
  - `userId`
  - `text`
  - `createdAt`
  - `updatedAt`

### 5.6 Удалить/редактировать комментарий (админ площадки)
- Редактирование:
  - `PATCH /api/v2/admin/news/comments/{commentId}`
- Удаление:
  - `DELETE /api/v2/admin/news/comments/{commentId}`
- Важно:
  - этот блок требует перехода с role-string на справочник ролей/прав (RBAC capability model).

### 5.7 Создать новость
- `POST /api/v2/admin/news`
- Поля:
  - `title`
  - `smallDescription`
  - `content` (markdown)
  - `image`

### 5.8 Лайк комментария
- `POST /api/v2/news/comments/{commentId}/likes`

### 5.9 Дизлайк комментария
- `POST /api/v2/news/comments/{commentId}/dislikes`

### 5.10 Дизлайк новости
- `POST /api/v2/news/{newsId}/dislikes`

### 5.11 Лайк новости
- `POST /api/v2/news/{newsId}/likes`

## 6. Пользователь

### 6.1 Удаление аккаунта
- `DELETE /api/v2/users/me`
- Назначение: удалить текущий аккаунт.

### 6.2 Поиск пользователей по нику и `@us`
- `GET /api/v2/users/search`
- Query: `q`
- Логика:
  - если `q` начинается с `@` -> приоритетный поиск по `us`,
  - иначе поиск по `name` и `us`.
- Ответ: список пользователей.
- Поля элемента:
  - `id`
  - `name`
  - `image`
  - `us`
  - `status`
  - `verified`

### 6.3 Получить профиль (свой/чужой)
- `GET /api/v2/users/profile`
- Query (опционально):
  - `userId` или `us`
- Логика:
  - без query -> профиль текущего пользователя,
  - с `userId/us` -> профиль другого пользователя (урезанный).
- Общие поля ответа:
  - `statistics`
  - `tiles`
  - `favoriteGenres`
  - `upcomingEvents`
  - `subscriptions`
  - `verified`
- Только для владельца:
  - `pastEvents` (последние 10)
  - `telegramConnected`
- Только при просмотре чужого профиля:
  - `mutualGroups` (группы, где состоите и вы, и он)

### 6.4 Отметить уведомление прочитанным
- `PATCH /api/v2/users/notifications/{notificationId}/read`

### 6.5 Получить уведомления (новые + старые до 10 дней)
- `GET /api/v2/users/notifications`
- Query: `page`, `limit`
- Правило хранения: старые уведомления доступны 10 дней.

### 6.6 Булевый рут «Есть ли новые уведомления»
- `GET /api/v2/users/notifications/has-new`
- Ответ:
  - `hasNew: bool`

### 6.7 Усиленный процесс смены пароля
- Цель: после проверки кода отправлять ссылку на смену пароля.
- Предлагаемый flow:
  1. `POST /api/v2/register/password/reset/request` — отправка кода на email.
  2. `POST /api/v2/register/password/reset/verify-code` — проверка кода, отправка письма со ссылкой.
  3. `POST /api/v2/register/password/reset/by-link` — смена пароля по токену из ссылки.

### 6.8 Изменение порядка/вида плиток профиля
- `PATCH /api/v2/users/me/tiles`

### 6.9 Обновление информации о себе
- `PATCH /api/v2/users/me/profile`

- Описать все новые роуты в Swagger.

## 8. Примечание по старому функционалу
Часть перечисленных возможностей уже исторически была в legacy-обработчиках (закомментированные/неактивные роуты), но теперь должна вернуться в `v2` с новым единым контрактом и тестами.

### 9.5 Верификация внутри сервиса
